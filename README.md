# NistCpeAISearch

CLI для сопоставления установленного ПО с тройкой `part/vendor/product` в словаре
NVD. DeepSeek выбирает поисковые действия через локальный MCP-сервер; программа
проверяет схему ответа и подтверждает точную тройку действующей записью CPE.
Версия ПО используется как контекст, а не как обязательный фильтр словаря.

Перед поиском по компонентам LLM преобразует сырое название в гипотезу
`part/vendor/product`: восстанавливает оригинальное имя, предполагает словарное
написание в ASCII без пробелов и экранирует специальные символы. Например,
«Корпорация Майкрософт» может дать гипотезу `microsoft`. Программа проверяет формат,
выполняет поиск и подтверждает результат в NVD; сама гипотеза ещё не является
соответствием. При ошибке формата модель получает пояснение и исправляет запрос.
Альтернативный поиск `keyword` допускает исходные названия с кириллицей и пробелами.
Преобразование выполняется в существующем цикле LLM, без отдельного запроса
предобработки для каждой строки; оригинальные поля отчёта сохраняются.

При отклонении итогового ответа модель получает конкретную причину: ошибку JSON,
имя отсутствующего/неверного поля или нарушенное правило сопоставления. Единственная
внешняя Markdown-обёртка вокруг JSON допускается; содержимое всё равно проходит
полную проверку схемы и NVD. Посторонний текст, `null` вместо строк и повреждённое
экранирование не исправляются догадками. Прерванная провайдером генерация сохраняет
причину `finish_reason` и не запускает цикл исправления пустого JSON.

## Установка и запуск

Требуется Python 3.11 или новее. Из корня проекта:

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -e .
.\venv\Scripts\python.exe -m cpe_matcher examples/report.csv -o result.csv
```

После установки также доступна команда `cpe-match`. Зависимости для приложения
описаны в `pyproject.toml`; исходный `requirements.txt` сохранён как снимок окружения.
Адаптер транспорта рассчитан на закреплённую версию `nvdlib==0.9.0`.

В существующем `.env` нужны `LLM_API_KEY`, `LLM_BASE_URL`, `DEFAULT_MODEL` и
`NIST_API_KEY`. Адрес и модель выбираются пользователем; значения не зашиты в код.
Файл не изменяется программой. Переменные окружения имеют приоритет над `.env`.
Другой файл можно указать через `--env-file`. MCP-сервер запускается автоматически
один раз на обработку файла и общается с CLI через stdio.

Вход — CSV UTF-8 (включая BOM) с обязательными столбцами:

```csv
input_vendor,input_product,input_version
Корпорация Майкрософт,"Microsoft Office, для дома и бизнеса 2010",14.0.6029.1000
```

Дополнительные столбцы игнорируются. Оригинальные строки, версии, порядок и повторы
сохраняются. Пустое название продукта получает `invalid_input`. Файлы `reports/`
и `mappings.csv` не изменяются; правила из последнего не участвуют в поиске.

## Результат и продолжение

Выходные столбцы:

```text
input_vendor,input_product,input_version,cpe_part,cpe_vendor,cpe_product,status,conclusion
```

| Статус | Значение |
|---|---|
| `matched` | Прямое соответствие, подтверждённое действующей CPE |
| `matched_parent` | Обоснованное приближённое соответствие основному продукту |
| `vendor_only` | Подтверждён только производитель |
| `ambiguous` | Несколько правдоподобных продуктов |
| `not_found` | Завершённый поиск не дал допустимого соответствия |
| `search_incomplete` | Поиск/проверка не завершены или достигнут защитный предел |
| `error` | Некорректный ответ модели |
| `invalid_input` | Недостаточно входных данных |

У `vendor_only` заполнен только производитель, у остальных неуспешных статусов
поля CPE пустые. `matched_parent` не доказывает установку основного продукта.
Семантическое обоснование выполняет LLM, поэтому даже подтверждённая словарём
тройка требует ручной оценки. Метрика точности пока не измерялась.

Каждый готовый результат сразу фиксируется в SQLite (`result.csv.sqlite3` по
умолчанию, либо `--state PATH`). Идентичные входные тройки обрабатываются один раз.
CSV атомарно формируется при завершении, обработанном сбое или Ctrl+C. При жёстком
завершении процесса может остаться предыдущий CSV; SQLite хранит завершённые записи.
Необработанные строки при экспорте получают `search_incomplete`.

```powershell
.\venv\Scripts\python.exe -m cpe_matcher examples/report.csv -o result.csv --resume
.\venv\Scripts\python.exe -m cpe_matcher examples/report.csv -o result.csv --resume --retry-status error
```

При продолжении автоматически повторяются `search_incomplete`; другие статусы
можно повторить через `--retry-status` (несколько раз). Состояние привязано к байтам
исходного файла и конфигурации, включая модель, адрес, лимиты и версию приложения.
Несовместимое состояние отклоняется. После изменения настроек нужен новый путь
состояния. Ключи не сохраняются в состоянии и могут быть заменены.

Сбой доступа, исчерпание повторов или потеря MCP останавливают весь запуск:
программа не создаёт волну ошибок для оставшихся строк. Текущая строка остаётся
незавершённой. Код возврата: `0` — обработка завершена (возможны отказы по строкам),
`1` — ошибка запуска/сервиса, `130` — Ctrl+C.

## Защитные настройки

Настройки можно добавить в окружение или `.env` самостоятельно:

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `MAX_LLM_STEPS` | 40 | Ответов LLM на уникальную входную тройку |
| `MAX_TOOL_CALLS` | 80 | Вызовов инструментов, включая финальную проверку |
| `LLM_MIN_INTERVAL` | 1 | Минимальный интервал начала запросов DeepSeek, секунды |
| `LLM_TIMEOUT` | 120 | Таймаут запроса DeepSeek, секунды |
| `LLM_MAX_RETRIES` | 4 | Повторов временной ошибки DeepSeek после первой попытки |
| `MCP_TIMEOUT` | 3600 | Таймаут одного MCP-вызова с учётом страниц и ожиданий, секунды |
| `NVD_MIN_INTERVAL` | 1 | Интервал HTTP-запросов NVD, минимум 0,6 секунды |
| `NVD_TIMEOUT` | 30 | Таймаут HTTP-запроса NVD, секунды |
| `NVD_MAX_RETRIES` | 4 | Повторов временной ошибки NVD после первой попытки |
| `NVD_MAX_PAGES` | 100 | Максимум страниц одного поиска/проверки |
| `NVD_PAGE_SIZE` | 1000 | Размер страницы NVD, от 1 до 2000 |

Обработка последовательная: один активный запрос к каждому сервису. NVD имеет
общий ограничитель 50 HTTP-запросов за скользящие 30 секунд, включая пагинацию
и повторы. Паузы DeepSeek независимы. Повторы используют увеличение задержки,
случайную добавку и `Retry-After`; внутренние повторы SDK отключены. Ожидание не
расходует поисковые шаги. Один общий API-ключ нельзя одновременно использовать
в двух запусках приложения на одном компьютере (блокировки ОС). Запуски на разных
компьютерах и другие приложения с теми же ключами этими блокировками не охватываются.

Результаты инструментов кэшируются только на время запуска. Полнота выдачи
передаётся модели; ограниченная выдача не считается доказанным отсутствием.
Проверка продукта перебирает версии до действующего подтверждения, полного
исчерпания словаря по фильтру либо предела страниц.

В stderr выводятся сообщения со временем и уровнем: чтение CSV, подключение MCP,
текущая строка и название ПО, шаг поиска, ожидание DeepSeek, поиск CPE/CVE,
обязательная проверка, использование кэша и сохранение результата. При временных
ошибках видны сервис, код HTTP (если есть) и длительность паузы перед повтором.
В конце выводятся количества статусов. `--verbose` дополнительно показывает
аргументы инструментов и номера страниц/попыток HTTP-запросов NVD. Ключи доступа
маскируются; полные ответы API и переписка модели не выводятся. Логи не записываются
в файл автоматически. В PowerShell их можно сохранить через `2> run.log`.
При невалидном итоговом JSON `--verbose` также показывает его длину и первые
160 символов для диагностики формата; внутренние рассуждения модели не выводятся.

## Проверки

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Проверки используют подставные ответы и не требуют ключей, платных запросов или
доступа к NVD. Включены CSV, сохранение и восстановление, 7000 синтетических строк,
блокировки запусков, проверки CPE, пагинация, повторы и цикл отклонения гипотез.
Реальные отчёты предназначены для последующей ручной оценки качества.

Протокол вызовов реализован по [документации DeepSeek](https://api-docs.deepseek.com/guides/tool_calls/),
включая сохранение `reasoning_content` между шагами, если его возвращает модель.
Ошибки доступа и баланса обрабатываются согласно
[кодам ошибок DeepSeek](https://api-docs.deepseek.com/quick_start/error_codes/).
